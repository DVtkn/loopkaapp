# AGENTS.md — Правила, архитектура и инструкции для AI-агентов

Этот файл содержит фундаментальные правила, архитектурные соглашения и стандарты разработки проекта **Loop** (приложение для укрепления отношений и эмоциональной близости пары с поддержкой ИИ-психолога «Сова»).

---

## 1. Общие принципы и язык разработки

1. **Язык общения и ответов**:
   - Все ответы, подсказки, пояснения и документация для пользователя **строго на русском языке**.
   - Код, комментарии к коду и интерфейсы по умолчанию адаптированы для русскоязычной аудитории (с корректной русской типографикой, ё/е, кавычками «ёлочками» и уважительным тоном).

2. **Соблюдение рамок пользовательского запроса**:
   - Реализовывать в точности то, что запросил пользователь.
   - Не добавлять лишних сторонних экранов или модулей без явного запроса.
   - Фокусироваться на безупречном визуальном исполнении, выверенных отступах, типографике и надёжности работы.

## 3. Правила работы с бэкендом и базой данных (`server.ts`)

- **Двойное хранилище (Dual-Storage Resilience)**:
  - Если настроена база данных Cloud SQL (PostgreSQL), данные сохраняются в SQL и зеркалируются в `/data/db_store.json`.
  - Если Cloud SQL временно недоступен или не настроен, приложение мгновенно и без ошибок переключается на постоянное JSON-хранилище в файле `/data/db_store.json`.
  - Никогда не ломать это резервирование: любые изменения в `users`, `pairRequests`, `coupleData` или `chatMessages` должны поддерживать сохранение в обе структуры.
- **Безопасность аутентификации**:
  - Пароли хешируются с использованием `bcryptjs` (salt rounds: 10).
  - Эндпоинт `/api/auth/login` защищён rate-лимитером от подбора паролей (5 неудачных попыток на IP+логин за 15 минут) и защитой от тайминг-атак.
- **Работа с ИИ (ИИ-психолог Сова)**:
  - Основной провайдер: **Groq API** с цепочкой fallback-моделей (`llama-3.3-70b-versatile`, `llama-3.1-8b-instant` и др.).
  - Если внешний API недоступен или лимит исчерпан, обязательно срабатывает встроенный локальный движок `generateSmartPsychologistReply()`, возвращающий эмпатичный, структурированный совет по методологии семейной психотерапии.
  - Форматирование ответов Совы: строго без markdown-таблиц и кода, компактный размер (70–130 слов), три смысловых блока: *«Взгляд психолога»*, *«Практика / Готовая фраза»*, *«Вопрос для вас»*.

## 4. Стандарты дизайна и типографики (Design System)

1. **Типографика**:
   - `h1`: `font-weight: 750`, `letter-spacing: -0.02em`, `line-height: 1.30`
   - `h2`: `font-weight: 700`, `letter-spacing: -0.016em`, `line-height: 1.33`
   - `h3`: `font-weight: 650`, `letter-spacing: -0.012em`, `line-height: 1.35`
   - `h4`: `font-weight: 600`, `letter-spacing: -0.01em`, `line-height: 1.40`
   - Основной текст параграфов (`p`): `line-height: 1.6` для комфортного длительного чтения.
   - Кнопки, табы, интерактивные бейджи: `font-weight: 600`, `cursor: pointer`.
2. **Цветовая палитра и темы**:
   - Приложение поддерживает светлую и тёмную темы через CSS-переменные: `--bg`, `--surface`, `--surface-2`, `--surface-3`, `--text`, `--text-2`, `--divider`, `--accent`, `--accent-2`.
   - Никогда не использовать чистые `#000000` или `#ffffff` без учёта палитры тем.
   - Все интерактивные кнопки должны иметь видимые состояния `:hover`, `:active` и плавные переходы (`transition-all`).
3. **Иконки**:
   - Строго из библиотеки `lucide-react`. Не использовать самодельный сырой SVG без необходимости.
4. **Анимации**:
   - Использовать `motion` (библиотека `motion/react` или `motion`) для плавных переходов экранов и списков.

## 5. Чек-лист перед завершением работы

0. **ЧЕК ПУНКТ 0: Ничего не откатывается на дефолт при структурных изменениях (КРИТИЧЕСКИ ВАЖНО)**:
   - **Иконки в карточках**: ВСЕГДА сохраняют цветную заливку-подложку (pastel square/circle с уникальным гармоничным цветом под тип действия — rose, amber, indigo, emerald, coral, purple и др.) — **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** заменять на голый контурный icon без цветного фона.
   - **Никаких дефолтных border/outline от UI-библиотеки**: если элемент имеет рамку, это осознанный токен (например, Primary CTA с акцентным градиентным бордером), а не случайный дефолт. Явно проверять каждый элемент на «случайную» серую рамку перед сдачей.
   - **Текст в подписях НЕ обрезается многоточием (`truncate`)**: подписи не должны обрываться многоточием (`...`). Размер контрола, перенос строк (`line-clamp-2`, `break-words`) или длина текста должны обеспечивать полное отображение без регрессий.
   - **Сохранение утверждённых визуальных токенов**: при любом рефакторинге сверять вид экрана: любой элемент, который был цветным/оформленным, обязан оставаться цветным/оформленным; меняться может только позиция/группировка, но не стиль и не цветность.

1. Проверить линтер: запустить `lint_applet` (должен проходить без ошибок TypeScript).
2. Проверить сборку: запустить `compile_applet` (сборка `npm run build` должна быть успешной).
3. Убедиться, что изменения не нарушили синхронизацию данных пары между вкладками и устройствами.

## 6. Definition of Done (DoD) & Functional QA
Ни одна задача не считается выполненной, если не пройдены все пункты:
1. **ФУНКЦИОНАЛЬНОСТЬ, НЕ ТОЛЬКО ВИЗУАЛ**: каждый интерактивный элемент (кнопка, тап, свайп, long-press) имеет проверенный обработчик, который выполняет заявленное действие end-to-end — включая запись/чтение из бэкенда, если действие подразумевает сохранение состояния.
2. **ПРОВЕРКА ДЛЯ P0-ФУНКЦИЙ ОБЯЗАТЕЛЬНА ДВУСТОРОННЕ**: если функция затрагивает обоих пользователей пары (создание пары, реалтайм-уведомления, общие данные) — проверить сценарий с двух сторон (пользователь А инициирует → пользователь Б получает и может отреагировать → оба видят согласованное состояние).
3. **РЕГРЕССИЯ ПРОТИВ УЖЕ ЗАФИКСИРОВАННЫХ ПРАВИЛ**: перед сдачей сверить экран с design-системой в PRD.md — НИКАКИХ ALL CAPS заголовков, обрезания текста многоточием (`truncate`), пустых placeholder-символов ("—" в незаполненных полях), обесцвеченных иконок.
4. **НИКАКИХ ДЕКОРАТИВНЫХ БЕЙДЖЕЙ БЕЗ ФУНКЦИИ**: если элемент выглядит как заявляющий о возможности ("В один тап", счётчик, статус) — эта возможность должна быть реализована (end-to-end), либо элемент не добавляется вообще.
5. **САМОПРОВЕРКА ПЕРЕД ОТЧЁТОМ**: Агент обязан явно и построчно пройти этот чек-лист перед тем, как отчитаться о готовности пользователю.

## 7. Внутренние скиллы Агента для проекта Loop
Агент обязан моделировать следующее поведение перед любой задачей:
- `prd-first`: Перед началом любой архитектурной задачи или изменения P0/P1 фич, прочитать файл `/PRD.md`. Любые изменения стека или структуры должны вноситься туда.
- `functional-qa`: Использование чек-листа DoD из пункта 6 перед коммитом задачи. 
- `design-system-compliance`: Строгое соблюдение описанных в `PRD.md` и пункте 4 `AGENTS.md` визуальных стандартов как единого источника правды (никаких собственных изобретений UI).
- `pair-e2e-testing`: Специфично для Loop — все данные пары тестируются с точки зрения синхронизации двух аккаунтов (например, через двойное окно браузера или логику `myLogin` / `partnerLogin`).
