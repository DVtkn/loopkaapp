## Миссия продукта
Loop — приложение для пар, основная цель которого: пары проходят психологические тесты, узнают больше друг о другe, находят и осознанно исправляют слабые места в отношениях. Вторичная, поддерживающая функция — быстрые проявления внимания (касания, вопрос дня, знаки заботы) — они существуют, чтобы удерживать ежедневное касание с приложением между сессиями глубокой работы над отношениями, а не как самоцель.

## Пользователи (персоны)

### Персона 1 — «Стабильная пара, ищущая профилактику»
Вместе 1–4 года, чаще всего живут вместе или на грани переезда друг к другу. Отношения не в кризисе, но есть ощущение рутины — меньше глубоких разговоров, чем в начале. Приходят в приложение не «спасать» отношения, а не дать им незаметно остыть.

- **Точка входа в продукт**: тест «5 языков любви» или «Карта Готтмана» — что-то с понятным немедленным результатом.
- **Первая ценность**: ИИ-отчёт, который называет вслух то, что оба чувствовали, но не проговаривали.
- **Причина уйти**: если тесты кончаются быстрее, чем формируется привычка возвращаться — нужен постоянный источник новых поводов для разговора (Deep Talk карточки, новый вопрос дня каждый день).

### Персона 2 — «Пара на дистанции»
Один или оба партнёра часто в разъездах или живут в разных городах. Главная боль — не рутина, а нехватка мелких сигналов присутствия друг друга.

- **Точка входа**: быстрые знаки внимания («Обнять», «Думаю о тебе») — единственный способ почувствовать касание за день.
- **Первая ценность**: партнёр реально видит уведомление в моменте, не через час.
- **Причина уйти**: если toast/push ненадёжны или с задержкой — вся ценность функции рушится, так как весь смысл в мгновенности.

### Персона 3 — «Пара, параллельно проходящая терапию»
Уже работают с психологом (очно или онлайн), ищут цифровой инструмент, который закрывает промежутки между сессиями — не заменяет терапевта, а даёт структуру для самостоятельной работы.

- **Точка входа**: ЭФТ-ориентированные тесты, «Радар гармонии» как способ визуализировать прогресс, который они обсуждают с терапевтом.
- **Первая ценность**: возможность закрепить инсайт из сессии конкретным действием в приложении (ответить на вопрос, пройти связанный тест).
- **Причина уйти**: если ИИ-психолог Сова даёт советы, противоречащие тому, что говорит их живой терапевт — доверие к продукту разрушается сразу и необратимо. Это самый чувствительный тип пользователя к качеству психологического контента.

## Пользовательские сценарии по фичам

Формат: **Что** пользователь делает → **Где** это происходит → **Зачем** это нужно (какую персону/потребность закрывает).

### P0 — Создание пары
- **Что**: отправить заявку по username или коду, партнёр принимает или отклоняет.
- **Где**: Профиль → «Связать».
- **Зачем**: без пары ни одна функция не имеет смысла — это ворота в продукт для всех трёх персон одновременно.
- **Нюанс сценария**: первая заявка обычно отправляется в момент, когда оба уже физически рядом (совместная установка приложения) — экран должен быть рассчитан на то, что человек делится кодом/логином голосом партнёру, а не по переписке. Отсюда — упрощённый «Код для связи» (`LOOP-XXXX`) как альтернатива поиску по username, если оба открыли приложение одновременно.

### P0 — Аутентификация и профиль
- **Что**: регистрация, логин, базовые настройки.
- **Где**: Профиль / Вход.
- **Зачем**: техническая база; для Персоны 3 особенно важна пометка «личное/приватное» в профиле — они уже привыкли к раздельным личным данным из терапии.

### P1 — Тесты совместимости
- **Что**: прохождение теста (5 языков любви / привязанность / Готтман / ЭФТ), получение сжатого превью-скора, полный ИИ-отчёт по завершении.
- **Где**: «Мы» → Паспорт → «Пройти тест» (под-экран, не в таббаре).
- **Зачем**:
  - *Персона 1*: единственный ясный «результат», который можно обсудить вечером за ужином.
  - *Персона 3*: количественная опора для разговора с терапевтом.
- **Нюанс сценария**: механика прохождения — **асинхронная** (каждый отвечает в своём темпе), отчёт формируется только когда ОБА завершили — иначе пара, живущая на дистанции (Персона 2), физически не сможет проходить тест одновременно.

### P1 — Deep Talk / Вопрос дня
- **Что**: один вопрос в день (тизер на «Сегодня»), библиотека вопросов (Deep Talk карточки) — доступна в любой момент на «Мы».
- **Где**: тизер на «Сегодня»; полная библиотека на «Мы».
- **Зачем**: это то, что удерживает Персону 1 после того, как тесты кончились — ежедневный, не иссякающий повод для разговора.
- **Нюанс сценария**: партнёр должен видеть, ответил ли уже второй (без содержания ответа — иначе теряется спонтанность, оба видят ответы друг друга только после того, как ответили сами, как в играх-icebreaker'ах).

### P2 — Быстрые знаки внимания
- **Что**: «Обнять» + long-press меню («Думаю о тебе», «Скучаю», «Поцелуй», «Ценю тебя»).
- **Где**: «Сегодня», Primary CTA.
- **Зачем**: ключевая функция для Персоны 2 (дистанция) — единственный «физический» контакт за день. Для Персоны 1 — низкопороговый повод открыть приложение в дни, когда нет настроения на глубокий тест.
- **Нюанс сценария**: должно быть мгновенным (realtime toast + push) — задержка убивает весь смысл для Персоны 2 критичнее, чем для остальных.

### P2 — XP и геймификация
- **Что**: очки опыта за действия, уровень пары, ачивки.
- **Где**: шапка приложения (глобально), модалка ачивок.
- **Зачем**: вторичный слой мотивации — важно не превратить его в самоцель (см. Non-goals: не про залипание). XP начисляется только за P0/P1-действия (тест, вопрос дня), не за сам факт открытия приложения — иначе система поощряет пустое присутствие, а не реальную работу над отношениями.

### P2 — Свидания
- **Что**: колесо идей, конструктор приглашения, места, история, игры.
- **Где**: отдельная вкладка «Свидания».
- **Зачем**: для Персоны 1 — противоядие от рутины физически, не только эмоционально. Для Персоны 2 — планирование редких очных встреч, поэтому конструктор приглашения должен уметь работать с датами «через месяц», а не только «сегодня вечером».

### P2 — Капсула времени
- **Что**: запечатанные письма/воспоминания с датой открытия в будущем.
- **Где**: «Мы» → Моменты.
- **Зачем**: долгосрочный якорь для всех персон — особенно ценен для Персоны 2, как способ «отправить» что-то через время, когда нельзя быть рядом физически.

### Чат — ИИ-психолог Сова
- **Что**: диалог с ИИ, режимы Соло / Вместе.
- **Где**: отдельная вкладка «Чат».
- **Зачем**: для Персоны 3 — критически чувствительная точка: Сова должна явно и часто напоминать, что не заменяет живого терапевта, и не давать советов, которые звучат как клинические диагнозы. Для Персоны 1 — более лёгкая точка входа в рефлексию, чем «настоящая» терапия.

## Приоритет фич
- **P0**: создание пары (связывание двух аккаунтов) — БЕЗ ЭТОГО НИ ОДНА ДРУГАЯ ФУНКЦИЯ НЕ ИМЕЕТ СМЫСЛА, так как весь продукт заточен под двух пользователей.
- **P0**: аутентификация, базовый профиль.
- **P1**: тесты совместимости (5 языков любви, типы привязанности, карта Готтмана, ЭФТ) + ИИ-отчёт с точками роста.
- **P1**: Deep Talk / вопрос дня — механика узнавания друг друга.
- **P2**: быстрые знаки внимания, XP/геймификация, свидания, капсула времени.

## Критерии приёмки (Acceptance Criteria)

### 1. Создание пары (P0)
* Пользователь может отправить заявку на привязку по `login` или короткому коду `linkCode` (`LOOP-XXXX`).
* Пользователь **НЕ** может отправить заявку самому себе (сервер возвращает HTTP `400` с кодом `INTERNAL_ERROR`).
* Пользователь **НЕ** может отправить заявку, если он сам или целевой пользователь уже состоят в подтверждённой паре (HTTP `400` `ALREADY_PAIRED`).
* Повторная отправка идентичной ожидающей заявки блокируется без дублирования записей в БД (идемпотентность).
* Получатель видит входящую заявку в интерфейсе профиля (через polling с задержкой не более 4 секунд).
* При принятии — оба пользователя видят обновлённый статус без перезагрузки (атомарная транзакция в БД с перекрёстной установкой `users.partnerLogin`).

### 2. Аутентификация и профиль (P0)
* Регистрация по уникальному логину (не менее 3 символов) и паролю (не менее 6 символов).
* Пароль надёжно хешируется на сервере (`bcryptjs`, 10 раундов); открытый пароль никогда не сохраняется и не логируется.
* Выдача криптографически подписанного JWT-токена с обязательной проверкой `JWT_SECRET` в продакшене (Fail-Fast).
* Неверный пароль или логин возвращает `401 Unauthorized` с защитой от тайминг-атак и защитой от перебора (максимум 5 попыток за 15 минут).
* Возможность настройки профиля (имя, аватар, статус настроения, город, дата начала отношений).

### 3. Тесты совместимости (P1)
* Доступны 4 психологические методики: «5 языков любви», «Типы привязанности», «Карта Готтмана», «ЭФТ паттерны».
* Асинхронное прохождение (Blind Test): партнёр отвечает в своём темпе, не видя ответов второго партнёра до завершения теста обоими.
* До завершения теста обоими партнёрами ответы на клиент партнёра не передаются (защита от подглядывания через DevTools).
* По завершении формируется ИИ-отчёт с Радаром отношений и начисляется фиксированный опыт пары (+100 XP).

### 4. Deep Talk / Вопрос дня (P1)
* Один актуальный вопрос в сутки на главном экране + библиотека карточек на вкладке «Мы».
* До отправки собственного ответа блок партнёра показывает только статус («Партнёр ещё думает» или «Партнёр ответил. Ответьте, чтобы прочитать»), текст ответа скрыт.
* После обоюдного ответа ответы обоих становятся видимыми с сохранением в архив истории пары.

### 5. ИИ-психолог «Сова» (P1)
* Чат с поддержкой режимов «Соло» и «Вместе».
* Ответ строго структурирован: *Взгляд психолога*, *Практика / Готовая фраза* («Я-сообщение»), *Вопрос для вас*.
* Groq API (`llama-3.3-70b-versatile` / `llama-3.1-8b-instant`) с автоматическим переключением на локальный движок `psychologyEngine.ts`.
* Обязательный дисклеймер: сервис носит рефлексивный характер и не заменяет живую терапию.

### 6. Быстрые знаки внимания (Touches) (P2)
* Отправка в 1 клик или через long-press меню («Обнять», «Думаю о тебе», «Скучаю», «Поцелуй», «Ценю тебя»).
* Доставка через Server-Sent Events (SSE) / Web Push с отображением всплывающего toast-уведомления.
* Защита от спама (троттлинг: не более 1 одинакового касания в 5 секунд).

### 7. XP-система и геймификация (P2)
* XP начисляется **только** за реальные обоюдные действия (тесты, вопросы дня, челленджи), но **не** за факт входа/открытия приложения.
* Серверная защита: поля `level`, `levelName`, `testsCompletedCount` отсекаются из клиентского пейлоада (`SECURITY STRIP`) и вычисляются сервером.

### 8. Свидания (P2)
* Колесо идей свиданий с фильтрацией по категориям и бюджетам.
* Конструктор приглашений с возможностью выбора даты как на ближайший вечер, так и на отдалённые даты («через месяц» для пар на дистанции).
* Двусторонний статус согласования: `PENDING_PARTNER`, «Принять», «Предложить другое».

## Жизненный цикл пары

### Разрыв пары (unpairing)
- Инициируется одним из партнёров, требует **явного двухшагового подтверждения**, чтобы исключить случайный разрыв.
- Второй партнёр получает уведомление о разрыве — без указания причины, **без возможности «отменить» разрыв со своей стороны** (решение того, кто инициировал, финально — иначе это создаёт токсичную динамику контроля внутри продукта).
- Данные (тесты, чат с Совой в режиме «Вместе», события) не удаляются сразу, а переводятся в **архивный readonly-статус** на обеих сторонах (каждый видит историю, но не может продолжать её).
- Приватные данные (чат в режиме «Соло») остаются полностью у того, кто их создал, и недоступны бывшему партнёру ни при каких условиях.

### Удаление аккаунта одним из партнёров
- Второй партнёр уведомляется, пара автоматически переходит в статус разрыва.
- Общие данные пары (`couple_data`, `ai_reports`) по умолчанию сохраняются в архиве для оставшегося партнёра (это его история отношений тоже), если только удаляющий аккаунт явно не запросил полное стирание общих данных (что требует согласия второго партнёра либо явного объяснения, что без согласия удаляются только персональные данные удаляющегося).

### Повторное создание пары после разрыва
- Разрешено технически, но вводится **защитный cooldown 24 часа** после разрыва перед тем, как аккаунт снова сможет отправлять или принимать заявки — защита от импульсивных решений «в порыве ссоры».

## Психологическая методология

### Принцип
Loop не заменяет клиническую диагностику. Все тесты — образовательные и рефлексивные инструменты, вдохновлённые публичными психологическими концепциями (Готтман, теория привязанности, 5 языков любви, ЭФТ), а не их сертифицированные клинические версии. Это явно зафиксировано в описании раздела «Тесты», чтобы не создавать ложного ощущения медицинской точности.

### Скоринг и ИИ-отчёт
- Каждый тест — авторская интерпретация методики, адаптированная под формат коротких вопросов в приложении, а не лицензированная клиническая шкала. Это осознанное продуктовое решение.
- ИИ-отчёт формируется из:
  1. Сырых баллов теста каждого партнёра;
  2. Шаблона промпта, который просит модель выделить 2–3 сильные стороны и 1–2 точки роста;
  3. Избегания категоричных формулировок («у вас проблема с X») в пользу описательных («в этой сфере у вас разный темп — вот тема для разговора»).

### Протокол безопасности при риск-индикаторах
- **Триггеры**: упоминания насилия (физического, эмоционального), суицидальных мыслей, самоповреждения — в любом канале со свободным текстом (чат с Совой, ответы на вопрос дня, Deep Talk).
- **Реакция системы**: Сова не пытается «терапевтировать» риск самостоятельно — переключается на короткий, некатегоричный ответ с контактами реальной помощи (кризисные линии), без осуждения и без просьб уточнить детали.
  - *Единый телефон доверия*: `8-800-2000-122`
  - *Кризисный центр для женщин*: `8-800-7000-600`
  - *Неотложная психологическая помощь*: `051` / `+7 (495) 051`
- **Изоляция реакции**: Это не блокирует остальной функционал пары. Если один партнёр написал что-то тревожное в режиме «Соло», это **не должно** автоматически становиться видимым второму партнёру (это может быть смертельно опасно в абьюзивных отношениях) — реакция системы адресована строго пишущему.

## Приватность

- **Тесты**: по умолчанию результаты видны обоим партнёрам строго после того, как оба завершили — не раньше и не частично.
- **Чат с Совой («Соло»)**: полностью приватен, не отображается партнёру ни в каком виде, включая метаданные («партнёр писал Сове 3 раза на этой неделе» — тоже скрыто).
- **Книга заботы / хотелки**: пользователь явно выбирает при создании записи — «видно партнёру» или «личное» (черновик, который сам ещё не готов показывать).
- **Удаление данных по запросу**: пользователь может запросить полное удаление своего аккаунта и всех лично принадлежащих ему данных в любой момент без объяснения причин.

## Метрики продукта

### Главная метрика (North Star Metric)
* **Доля пар, ответивших на «Вопрос дня» или прошедших тест минимум 3 раза за первые 14 дней после создания пары** — лучший ранний индикатор того, что пара нашла в продукте повторяющуюся ценность, а не просто разово попробовала.

### Вторичные метрики по уровням
* **P0**: % успешно созданных пар от числа отправленных заявок (низкий процент свидетельствует о барьере в UX принятия заявки).
* **P1**: среднее число тестов, пройденных парой за первый месяц; % пар, удерживающих непрерывную серию ответов на Вопрос дня 5+ дней подряд (стрик).
* **P2**: корреляция между ростом XP и retention (проверка, работает ли геймификация как стимул вернуться).

### Что осознанно НЕ измеряем как цель
* **Общее время в приложении в день**: Цель продукта — качество отношений вне приложения; длительное зависание в приложении — не признак успеха, а часто симптом компенсации нехватки живого контакта.

## IA-карта приложения
Приложение состоит из 5 основных вкладок таббара:
1. **Сегодня (DashboardView)**: Главный экран (статус партнёра, быстрые эмоции/касания по long-press, Вопрос дня, виджеты трендов).

5. **Профиль (SettingsView / UserProfileCabinet)**: Личный кабинет, привязка партнёра, управление заявками в пару, настройки.

## Дизайн-система
Единый источник правды компонентов (src/components/ui/SystemBlocks.tsx):

- ALL CAPS запрещён (все заголовки sentence case).
- Обрезание текста многоточием (`truncate`) запрещено, текст должен переноситься (line-clamp).
- Никаких пустых placeholder-символов ("—") в незаполненных полях (скрывать элемент полностью).
- Иконки всегда с цветной заливкой-подложкой (pastel-фоны: bg-rose-500/10 и т.д.).
- Никаких декоративных бейджей или текстов без функционала за ними.

## Технический стек
- **Фронтенд**: React 18, TypeScript, Vite, Tailwind CSS, Framer Motion, Recharts.
- **Бэкенд**: Собственный Node.js / Express сервер (`server.ts`). (Без использования Firebase / Supabase).
- **База данных**: PostgreSQL (через платформу Neon) с использованием Drizzle ORM + резервный фоллбэк в JSON (`/data/db_store.json`).
- **Realtime / Синхронизация**: Клиентский polling (через React Context / `apiFetch` каждые N секунд) + Web Push API для уведомлений.
- **ИИ**: Groq API (с фоллбэк цепочкой локальных правил `psychologyEngine.ts`).

## Non-goals
- Не социальная сеть (никакой ленты новостей от других пар).
- Не дневник для одного пользователя (приложение требует партнёра для раскрытия ценности).
- Не универсальный календарь/таск-менеджер для не-пар.
