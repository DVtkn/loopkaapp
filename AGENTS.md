# AGENTS.md — Правила, архитектура и инструкции для AI-агентов

Этот файл содержит фундаментальные правила, архитектурные соглашения и стандарты разработки проекта **Loop** (приложение для укрепления отношений и эмоциональной близости пары с поддержкой ИИ-психолога «Сова»). Данный документ является Единым Источником Правды (SSOT) для всех AI-агентов, вносящих изменения в кодовую базу.

---

## 1. Absolute Constraints (Категорические запреты)

1. ❌ **ЗАПРЕЩЕНО** использовать моковые данные, заглушки со статическими процентами (58%, 59%, 65%) и константы вида «Dmitry и Anna завершили 7 из 7» в продакшен-коде. Если в базе нет отчёта, UI обязан отображать пустое состояние (Empty State).
2. ❌ **ЗАПРЕЩЕНО** использовать слово «якорь» в любых сгенерированных названиях, архетипах союза или fallback-значениях. Архетипы формируются строго как комбинация двух ведущих сфер (например, «Надёжная гавань & Общий горизонт»).
3. ❌ **ЗАПРЕЩЕНО** использовать `db_store.json` в продакшене. В качестве базы данных используется ТОЛЬКО Neon PostgreSQL + Drizzle ORM.
4. ❌ **ЗАПРЕЩЕНО** определять статус завершения теста пользователем по наличию ответов в паре (`coupleId`). Статус проверяется строго по условию `testAnswers.userId === req.user.id`.

---

## 2. Frontend UI Guidelines & Tabs Isolation

1. **Изоляция вкладок (Tabs Isolation)**:
   - Экран аналитики (`ReportView.tsx` / `RelationshipRadar.tsx`) обязан соблюдать строгую изоляцию табов.
   - При `activeTab === 'partner'` рендерить ТОЛЬКО личные шкалы партнёра (если сданы) или карточку «Нет данных» с ранним выходом (`return`).
   - Запрещено сквозное просачивание разбора 6 сфер союза в персональные вкладки.
2. **Карточки тестов**:
   - В карточках тестов бейдж «Вы прошли» показывается строго по условию `isCompletedByMe === true`.

---

## 3. Testing & Verification Standard

1. **Тестирование изменений**:
   - Любое изменение в логике тестов, скоринга или изоляции данных обязано сопровождаться запуском тестов Vitest/Playwright (`npm run test`).
2. **Сборка перед коммитом**:
   - Перед каждым коммитом обязательна успешная сборка проекта: `npm run build`.

---

## 4. Общие принципы и язык разработки

1. **Язык общения и ответов**:
   - Все ответы, подсказки, пояснения и документация для пользователя **строго на русском языке**.
   - Код, комментарии к коду и интерфейсы по умолчанию адаптированы для русскоязычной аудитории (с корректной русской типографикой, ё/е, кавычками «ёлочками» и уважительным тоном).
2. **Соблюдение рамок пользовательского запроса**:
   - Реализовывать в точности то, что запросил пользователь. Не добавлять лишних экранов без явного запроса.

---

## 5. Архитектура проекта и стек технологий

- Основной фреймворк: **React 18/19 (Vite) + TypeScript**.
- Стилизация: **Tailwind CSS**.
- База данных: **Neon PostgreSQL** с Drizzle ORM.
- AI-интеграция: **Groq API** (модель `qwen/qwen3.8-27b`), с локальным фоллбэком.

---

## 6. Стандарты дизайна и типографики (Design System)

1. **Типографика**:
   - Заголовки (h1-h4) имеют плотный `letter-spacing` (от `-0.02em` до `-0.01em`) и `font-weight` от 600 до 750.
   - Основной текст параграфов (`p`): `line-height: 1.6`.
2. **Цветовая палитра и темы**:
   - Использовать CSS-переменные для тем: `--bg`, `--surface`, `--text`, `--accent`, и др.
   - Никогда не использовать чистые `#000000` или `#ffffff` без учёта палитры тем.
3. **Иконки**:
   - Строго из библиотеки `lucide-react`. Не использовать самодельный сырой SVG.
4. **Анимации**:
   - Использовать библиотеку `motion` (`motion/react`) для плавных переходов.

---

## 7. Definition of Done (DoD) & Functional QA

Ни одна задача не считается выполненной, если не пройдены все пункты:
1. **Функциональность**: Каждый интерактивный элемент имеет проверенный обработчик.
2. **Двусторонняя проверка**: Если функция затрагивает обоих пользователей пары, проверить сценарий с двух сторон (изоляция, синхронизация).
3. **Регрессия**: Соблюдение визуальных токенов. Никаких дефолтных border/outline от UI-библиотеки. Подписи не обрезаются многоточием (`truncate`). Иконки в карточках сохраняют цветную подложку.

## 8. Внутренние скиллы Агента для проекта Loop

Агент обязан моделировать следующее поведение перед любой задачей:
- `prd-first`: Перед началом любой архитектурной задачи прочитать `PRD.md`.
- `functional-qa`: Использовать чек-лист DoD перед коммитом задачи.
- `design-system-compliance`: Строгое соблюдение визуальных стандартов `PRD.md` и `AGENTS.md`.
- `pair-e2e-testing`: Проверка данных с точки зрения синхронизации и изоляции двух аккаунтов.
